## Why I started building in public

I've spent 15+ years building the software layer that most people never see — the framework beneath the infotainment screen, the middleware between Android and the vehicle, the SDK that other engineers build on top of.

Now I'm doing something new.

I'm integrating **Model Context Protocol (MCP)** into Android Automotive extension frameworks — enabling AI agents to make structured API calls to vehicle platform services on behalf of developers. This is not a prototype. This is live, production-grade work happening right now.

The gap between embedded automotive systems and AI agent architecture is closing. I'm building the bridge.

---

## 🚗 What I'm building now

At **Acsia Technologies** (current):

| Project | What it is |
|---------|-----------|
| 🏗️ **Android Automotive Extension Framework** | Core SDK layer enabling OEM system apps and third-party developers to integrate with vehicle platform APIs cleanly, without direct VHAL access |
| ⚡ **Custom VHAL gRPC Service** | Built from scratch for the Android Automotive emulator — full control over all VHAL properties (display, location, sensors, vehicle signals) + Cuttlefish virtual device management |
| 🛠️ **Custom Developer Tooling** | A developer tool that mirrors Android Studio's Extended Controls — full VHAL property control, display management, location simulation in a single interface |
| 🤖 **MCP + AI Agent Integration** | Integrating [Model Context Protocol](https://modelcontextprotocol.io) into the extension framework so AI agents can make structured API calls to vehicle platform services — bridging AAOS with LLM-driven agent architecture |
